#02. INTRODUCCIÓN
dns

¿Qué es la instalación y configuración de servidores?

Es el proceso de despliegue y puesta en marcha de un sistema operativo especializado, diseñado para proveer servicios de red continuos —como alojamiento web (HTTP) y administración remota segura (SSH)— a múltiples equipos clientes de manera simultánea.

verified_user

Importancia para el técnico informático

Dominar esta labor es fundamental porque garantiza la disponibilidad de los servicios críticos, asegura una conectividad estable mediante direccionamiento IP fijo y establece una seguridad perimetral sólida mediante cortafuegos antes de exponer el sistema a la red.

#04. FUNDAMENTOS TÉCNICOS
hub MODELO CLIENTE-SERVIDOR

Arquitectura Cliente-Servidor

Modelo de comunicación donde el servidor (servidor-01) centraliza recursos y escucha peticiones entrantes, mientras los clientes (como Windows) envían solicitudes y reciben respuestas procesadas.

terminal EFICIENCIA DE RECURSOS

Servidor sin Interfaz Gráfica (CLI)

Operar exclusivamente mediante línea de comandos reduce drásticamente el consumo de memoria RAM y CPU, minimiza la superficie de ataque y permite una administración precisa y automatizable.

lan DIRECCIONAMIENTO PERSISTENTE

IP Estática vs. DHCP

Mientras DHCP asigna direcciones temporales que pueden cambiar tras un reinicio, una IP estática garantiza que el servidor sea siempre localizable en la misma dirección (192.168.196.150).

PUERTO 22 / TCP lock

Protocolo SSH (Puerto 22)

Secure Shell cifra toda la comunicación de terminal para administrar el servidor de forma remota sin exponer credenciales en texto plano a través de la infraestructura local.

PUERTO 80 / TCP language

Protocolo HTTP (Puerto 80)

Hypertext Transfer Protocol permite entregar páginas y recursos web desde Apache2 hacia los navegadores de los clientes conectados al segmento de red.

#06. PROCEDIMIENTO PASO A PASO
PASO 01 VirtualBox Setup

Red en VirtualBox

Configura el adaptador de red de la máquina virtual en modo “Adaptador puente” para integrarla directamente a la red local y permitir comunicación directa con Windows.

Ajustes de VM → Red → Conectado a: Adaptador puente (Realtek RTL8822CE)
PASO 02 OS Deployment

Instalación e Inicio de Sesión

Instala Ubuntu Server 26.04.1 LTS con OpenSSH habilitado e inicia sesión en consola interactiva como nikotina@servidor-01.

Ubuntu Server 26.04.1 LTS servidor-01 tty1
servidor-01 login: nikotina
PASO 03 Network Inspect

Identificar Interfaz y Gateway

Verifica la interfaz de red (enp0s3) y la puerta de enlace predeterminada (192.168.196.203).

bash 
ip a
ip route show default
PASO 04 YAML Configuration

Configurar IP Estática en Netplan

Edita /etc/netplan/00-installer-config.yaml con sudo nano y aplica los cambios con sudo netplan apply:

/etc/netplan/00-installer-config.yaml 
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses:
        - 192.168.196.150/24
      routes:
        - to: default
          via: 192.168.196.203
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
PASO 05 Web Server

Instalar Apache2

Actualiza los índices de repositorios del sistema e instala el servidor web Apache2 en segundo plano.

bash 
sudo apt update && sudo apt install apache2 -y
PASO 06 UFW Firewall

Configurar Firewall UFW

Permite explícitamente el tráfico de OpenSSH y HTTP (puerto 80 TCP) antes de activar el cortafuegos.

bash 
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw enable
sudo ufw status
PASO 07 Client-Side Verification

Verificar Servicios y Probar desde Cliente

Comprueba ambos servicios en el servidor y realiza pruebas de conectividad desde Windows (PowerShell y navegador web en http://192.168.196.150):

PowerShell / Linux Terminal 
systemctl status ssh apache2 --no-pager
ping 192.168.196.150
ssh nikotina@192.168.196.150

#09. RESOLUCIÓN DE PROBLEMAS Y DIAGNÓSTICO
warning INCIDENCIA 01

sudo: 'dhclient': command not found

Causa: La utilidad tradicional dhclient no viene preinstalada en esta versión de Ubuntu Server, la cual delega la gestión a systemd-networkd.

Solución Técnica: No se requirió ninguna instalación adicional. Se prescindió del comando dado que la meta era fijar la IP estática directamente mediante el archivo de Netplan.

cloud_off INCIDENCIA 02

Aislamiento de red en modo NAT

Causa: El modo NAT por defecto en VirtualBox aísla la máquina virtual en un segmento privado (10.0.2.x), impidiendo que el anfitrión Windows alcance sus puertos directamente.

Solución Técnica: Modificar el adaptador de red en la configuración de la VM a Adaptador puente, logrando que el servidor obtenga presencia en la red física real.

shield_with_heart INCIDENCIA 03

Bloqueo tras activar UFW

Causa: Activar el cortafuegos antes de registrar las reglas provoca el bloqueo total de puertos entrantes, cerrando cualquier sesión de administración remota.

Solución Técnica: Ejecutar con antelación sudo ufw allow OpenSSH y sudo ufw allow 80/tcp asegurando la continuidad operativa antes de hacer enable.
